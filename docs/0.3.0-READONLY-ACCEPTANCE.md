# Dvinholm 0.3.0: read-only ECU snapshot acceptance checklist

**Status (2026-10-27): Development integration stage. Not a released
Stable version.** Published Stable v0.2.4 is unchanged. This checklist
separates *automated synthetic acceptance* from *Windows user acceptance*
and *actual Volvo P2/CEM compatibility*.

## Eight automated cross-component acceptance gates

Run the `VolvoP2CemReadOnlyAcceptanceTests` suite on the Development
branch, within the existing Windows x86 GitHub CI. Tests use an injected,
synthetic UDS `0x22` DID read function, not a real vehicle.

| Gate | Expected behavior |
| --- | --- |
| 1. Capture → JSON → inspect | Exact opaque DID bytes and CAN metadata survive the round trip; flagged sensitive and non-restorable |
| 2. Two captures → diff | Matching profiles/addresses/DID sets compare; changed DID identifiers are detected without exposing bytes in the UI summary |
| 3. Deterministic DID order | DIDs read and exported in ascending order, without extra requests |
| 4. Partial read failure | Wrong echoed DID aborts the whole readback; no complete partial baseline is returned |
| 5. Cancellation | A cancelled multi-DID capture stops and returns no complete record |
| 6. Export corruption | Modified raw DID bytes with unchanged SHA-256 are rejected before comparison |
| 7. Evidence-scoped CEM identification | An explicitly sourced **synthetic** multi-DID signature and matching year permit *read-only* identity/observed DID classification; no PIN/write permissions |
| 8. Fail-closed compatibility | Invalid candidate catalog, changed firmware signature and unsupported model year return unknown rather than guessing support |

## Windows user acceptance (not claimed by green CI)

When a supported Development x86 package is installed on Windows 11 LTSC:

- Verify profiles, J2534 adapter selection and existing CAN Monitor and UDS actions still work with the **virtual adapter**, without a physical vehicle.
- Confirm **Read + save DID snapshot** is disabled while disconnected, during other UDS operations and for missing/edited profile addressing.
- Confirm the pre-read consent dialog can be cancelled with **no CAN requests**, and Save As cancel does not create a file.
- Confirm saved JSON is user-directed, sensitive and clearly **not restorable**; saving inside the application folder is refused.
- Verify **Inspect saved snapshot** works disconnected, ignores corrupt/oversize JSON, never changes profile selection, and hides raw values.
- Verify **Compare saved snapshots** handles equal, modified and incompatible synthetic DID sets, reporting identifiers/counts without exposing values.
- Confirm switching Development/Stable updater channels and updating the app preserve saved user settings.
- Confirm read-only P2/CEM support is **unknown** without independently sourced firmware evidence, even for an XC90 P2 profile or model-year claim.

These manual/virtual adapter observations must be **reported as completed
only if actually performed**. Automated xUnit checks and ZIP audits do not
substitute for launching WinUI and inspecting it on Windows.

## Unsupported / future gate

No verified production XC90 P2/CEM signatures or configuration address map
have been populated. The `VolvoP2CemSupportMatrix.ProductionEntries` catalog
is intentionally empty. PIN discovery/authentication, immobilizer operations,
vehicle coding/write, and restorable backup do not exist in 0.3.0.

Real hardware acceptance with an authorized, compatible J2534 and ECU is
deferred. A future write feature **must** pass separate physical test and
safety criteria before publishing Stable. No release is published simply
because CI is green; explicit user approval remains required.
