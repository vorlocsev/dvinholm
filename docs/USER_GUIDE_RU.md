# Dvinholm — руководство пользователя (RU)

> Для Dvinholm **v0.2.1** и новых CI-сборок из `main`. Некоторые улучшения читаемости DID/DTC есть только в новых CI-сборках, пока они не вошли в следующий стабильный релиз.
>
> **Важно:** совместимость с реальным J2534-адаптером, драйверами и автомобилями пока **не подтверждена**. Тесты с виртуальным адаптером проверяют программную логику, но не работу оборудования. Dvinholm — независимый проект, не связанный с Volvo Cars.

## Для чего программа

Dvinholm — переносимое **Windows x86**-приложение для наблюдения за **CAN** и чтения некоторых диагностических данных по **ISO-TP/UDS** через адаптер с драйвером **SAE J2534**.

Текущие функции:

- просмотр сырых CAN-кадров с фильтрацией по ID, статистикой, счётчиком потерь и экспортом CSV;
- пассивное обнаружение возможных UDS-ответчиков (без опроса ECU);
- чтение DID (`0x22`), VIN через `F190` и DTC через `0x19/0x02`;
- импорт, экспорт и сохранение каталога ECU-профилей;
- проверка и установка успешных CI-сборок **ветки `main`**.

**Чего пока нет:** подтверждённых адресов ECU для конкретного Volvo XC90, полной базы расшифровки неисправностей Volvo, записи/программирования ECU, сброса ошибок, функций Security Access, ключей и PIN.

## 1. Первый запуск — без адаптера

1. Скачайте [стабильный ZIP v0.2.1](https://github.com/vorlocsev/dvinholm/releases/tag/v0.2.1).
2. **Полностью распакуйте** архив в отдельную папку, например `C:\Dvinholm`. Не запускайте программу внутри ZIP.
3. Откройте `Dvinholm.App.exe`.
4. Проверьте наличие значка Dvinholm, кнопки **Check update**, раздела **ECU profiles** и поля **CAN speed**.
5. Выберите скорость, например **125 kbit/s**, перезапустите Dvinholm и проверьте, что значение осталось выбранным.
6. Нажмите **Add test profiles**, затем переключайтесь между двумя тестовыми профилями. Проверьте, что Request/Response ID меняются.

Без физического устройства сообщение **Connection failed** ожидаемо, а **Start monitor / Read VIN / Read DTC / Discover ECUs** неактивны до подключения.

Два встроенных профиля **TEST — Standard CAN (11-bit)** и **TEST — Extended CAN (29-bit)** предназначены **только для проверки интерфейса**. Их адреса и DIDs не подтверждены для конкретного автомобиля.

## 2. Адаптер и соединение с CAN

Необходим J2534-совместимый интерфейс с **32-битной J2534 DLL и драйвером производителя**. Наличие подходящего DLL в системе не доказывает совместимость с Dvinholm; Volvo DiCE и Mongoose пока не проверены с реальным оборудованием.

1. Установите драйвер производителя с 32-битным J2534-компонентом.
2. Подключайте оборудование к автомобилю по инструкции производителя. Первое тестирование проводите на стоящем автомобиле.
3. В Dvinholm нажмите **Refresh** возле **Registered adapters**.
4. Выберите найденный адаптер. Если его нет, укажите путь к 32-битной DLL в поле **J2534 DLL**.
5. Укажите **CAN speed** — **125**, **250** или **500 kbit/s** — **только по подтверждённым характеристикам нужной сети**. Не выбирайте скорость наугад.
6. Нажмите **Connect**. При удаче увидите `Connected · J2534 · CAN` и, если драйвер поддерживает, версии API/DLL/FW.

При `Connection failed` проверьте физическое устройство, установленный драйвер, разрядность DLL, документацию производителя, скорость и подключение. Не повторяйте активные диагностические запросы бесконечно.

## 3. CAN Monitor — начинать рекомендуется отсюда

После успешного подключения нажмите **Start monitor**.

В списке:

| Столбец | Что означает |
| --- | --- |
| Timestamp (ms) | Время кадра |
| ID | CAN Arbitration ID в HEX |
| Type | 11-bit или 29-bit |
| DLC | Длина данных |
| Data | Байты данных в HEX |

- **ID filter (hex)** показывает кадры с конкретным ID, например `7E8`, или `0x7E8`. Это фильтр отображения.
- **Clear** очищает показанные кадры; **CSV log** экспортирует записи текущего списка в файл CSV.
- Справа отображаются число кадров, скорость приёма и число потерянных кадров (`dropped`). При потерях запись может оказаться неполной.
- **Apply HW filter** — отдельная, необязательная функция фильтра в самом J2534-драйвере. Она может не поддерживаться конкретным оборудованием; не путайте её с обычным **ID filter**.
- **Stop monitor** завершает отображение; **Disconnect** закрывает сессию.

Список в окне ограничен последними записями (не более 5000 элементов); CSV содержит текущий отображаемый список, а не гарантированно весь трафик с начала захвата.

**CAN Monitor показывает сырые сообщения**: без проверенных определений кадров он не выводит температуру двигателя, давление или причины неисправностей.

## 4. Discover ECUs — пассивное обнаружение

Нажмите **Discover ECUs** после подключения. Dvinholm **8 секунд только слушает** трафик и ищет возможные UDS-ответы. Запросов ECU функция **не посылает**.

В таблице могут появиться Response ID, предполагаемый Request ID, формат адресации и число наблюдавшихся кадров. **Request ID может быть лишь выведен из распространённой схемы адресации** — обязательно проверьте его по документации.

Если `No UDS responses observed`, это **не** означает, что блоков в автомобиле нет: возможно, во время наблюдения просто не было диагностических ответов.

**Cancel scan** позволяет прервать сканирование. При потере кадров результат отмечается как неполный (улучшение учёта потерь присутствует в новых CI-сборках).

## 5. ECU profiles — адреса и настройки блоков

Каждый профиль содержит название ECU, CAN Request/Response ID, 11-/29-битную адресацию, список предполагаемых DID и примечание о происхождении информации.

- **Add test profiles** добавляет два синтетических демонстрационных профиля (не для реального автомобиля).
- **Import JSON** загружает каталог из JSON-файла; импорт проверяет структуру и дубликаты ID.
- **Export JSON** сохраняет текущий каталог в файл.
- Выбор профиля переносит сохранённые адреса в поля UDS **без передачи запроса в автомобиль**.
- Профили сохраняются в `%LOCALAPPDATA%\Dvinholm\ecu-profiles.json`.

Пример **только учебного**, не подтверждённого для конкретной ECU профиля:

```json
[
  {
    "id": "demo.ecu.unverified",
    "name": "Demo ECU — test only",
    "requestId": "7E0",
    "responseId": "7E8",
    "isExtended": false,
    "readableDataIdentifiers": ["F190"],
    "source": "Synthetic fixture only; not verified for any vehicle.",
    "isVerified": false
  }
]
```

Не устанавливайте `isVerified: true` без подтверждения адресов и доступных DID на конкретном ECU.

## 6. Read DID / Read VIN / Read DTC

**Только после успешного подключения и проверки правильных адресов ECU:**

- **UDS request ID** — CAN ID отправляемого диагностического запроса;
- **UDS response ID** — CAN ID ожидаемого ответа;
- **CAN ID format** — 11-bit или 29-bit;
- **DID (hex)** — идентификатор данных, например `F190`.

**Read DID** отправляет UDS `0x22`. Новые CI-сборки показывают DID, сырые байты, а для `F190` — корректный VIN. Для других DID возможен **неподтверждённый ASCII preview**, но программа **не выдумывает единицы измерения**.

**Read VIN** запрашивает `F190`, ожидает корректный VIN длиной 17 символов. Блок ECU может не поддерживать такой запрос.

**Read DTC** отправляет `0x19 / 0x02` с маской `FF`. В новых CI-сборках каждый 24-битный код показывается отдельно с исходным статусом и стандартными признаками: `confirmed DTC`, `pending DTC` и другими. **Описание причины неисправности Volvo без проверенного справочника не предоставляется.**

**Cancel UDS** отменяет текущий запрос. Ответ `timeout` означает отсутствие корректного ответа в отведённое время; `NRC` указывает на диагностический отказ ECU. Отсутствие кодов от **одного** блока по **одной** маске не означает, что во всём автомобиле нет ошибок.

Все перечисленные диагностические операции в Dvinholm **только читают данные**; команда стирания DTC не реализована.

## 7. Обновления и файлы пользователя

Кнопка **Check update** ищет последнюю **успешную CI-сборку из `main`**, для которой опубликован доступный ZIP. Это **не** то же самое, что установка последнего стабильного релиза: CI-сборка может содержать более новые экспериментальные изменения.

Когда новая сборка найдена, появляется **Replace files and restart**. Обновлятор заменяет файлы приложения в **текущем каталоге запуска**, включая удаление устаревших файлов. Поэтому распаковывайте Dvinholm **в отдельную папку** и не храните в ней личные файлы. Для возврата к конкретному стабильному выпуску скачайте его ZIP со страницы Releases и распакуйте в отдельную папку.

Профили находятся в `%LOCALAPPDATA%\Dvinholm\ecu-profiles.json` отдельно от каталога приложения. При ошибках обновления смотрите `%LOCALAPPDATA%\Dvinholm\update.log`. Перед значимыми изменениями полезно экспортировать каталог профилей в JSON.

## 8. Частые вопросы

**Почему кнопки мониторинга и чтения неактивны?** Нет успешной J2534/CAN-сессии — это ожидаемо без адаптера.

**Почему программа пишет `No UDS responses observed`?** Пассивный поиск не вызывает ответы самостоятельно.

**Почему `Read VIN` / `Read DTC` выдаёт `timeout` или NRC?** Возможны неправильные адреса/скорость, неподдерживаемый DID/сервис, особенности ECU или проблемы с адаптером. Не делайте выводов без подтверждённых данных.

**Можно ли использовать обычный ELM327?** Не напрямую: приложение требует J2534-драйвер, а не произвольный ELM327/Bluetooth-протокол.

**Можно ли сбросить ошибки или прошить ECU?** Нет, нынешние диагностические сервисы намеренно ограничены чтением.

**Это замена VIDA?** Пока нет. Dvinholm предоставляет низкоуровневые CAN/UDS-инструменты, но не содержит подтверждённой базы сервисных функций и данных Volvo.
