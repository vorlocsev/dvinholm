### Stage 544: reject invalid UIA scroll percentages (offline source guard)

Windows UI Automation can return a non-finite or out-of-range vertical scroll percentage when a peer is unreliable. A comparison such as `$atBottom -lt 98` alone does **not** reject `NaN`: both less-than and greater-than comparisons with `NaN` return false. The capture helper now explicitly rejects `NaN`, positive/negative infinity and out-of-range numbers in the original scroll position (must be 0–100%), measured bottom position (98–100%), and final pre-pixel bottom recheck (98–100%). It likewise rejects non-finite values in both first-fold measurements (0–2%). A bad value fails closed and cannot be recorded as verified UIA evidence.

This is a correction to screenshot evidence acquisition, not to the WinUI layout or vehicle stack. Seven added test methods guard the numeric checks, their ordering ahead of screenshot writes and the absence of CAN/J2534/network operations. Windows CI can validate the code and parse the PowerShell helper but cannot substitute for a real interactive desktop scroll test or manual image inspection. Do not mark visual parity **PASS** based solely on these contracts.

### Stage 545: WinUI first-fold stability after navigation (requires real desktop review)

In the fixed 1280 × 800 DIP Aurora shell, selected ECU, diagnostics, or Connection fields can claim focus while a new page is still finishing its WinUI layout. A single synchronous `WorkspaceScroll.ChangeView(null, 0, null)` after focus could therefore be superseded by a later layout-driven scroll, skipping the intended first card. Stale work from a previous page must never scroll the next page.

These callbacks only adjust the presentation of the outer workspace. They do not connect J2534, contact an ECU, start an update, change the selected page or move keyboard focus. Five static regression tests validate the ordering, generation guard and restricted actions. Actual first-fold and focus acceptance remains **NOT RUN** until an interactive Windows check.
