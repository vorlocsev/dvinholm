# Dvinholm unified x64: Windows installation and J2534 manual acceptance

**Status: pending hands-on Windows review.** This is an acceptance checklist, not a record of successful physical adapter tests. PR-only CI ZIPs are not signed releases, and production update replacement stays disabled.

## Preparation

Use an isolated Windows 11 x64 test machine with a known restore point / disposable installation. Obtain the ZIP only from the GitHub Actions artifact for the **exact PR head commit** whose automated x64 pilot and full regression runs both passed. Do not treat successful publishing as Windows GUI acceptance. Never use an actual vehicle or live CEM PIN/configuration service for this checklist.

## Optional real desktop screenshot collection (NOT RUN)

This is **not** part of GitHub Actions. The unsigned PR review artifact now includes `eng/Capture-UnifiedAuroraWinUI3.ps1` **beside**, not inside, the production-mode Dvinholm ZIP. Review the helper text before running it; do not execute a modified or mismatched-head copy. Select the intended RU or EN language in Dvinholm manually. Use Windows PowerShell 5.1 (`powershell.exe`), not `pwsh`; run from a trusted checkout and review the script first.
```powershell
powershell.exe -NoProfile -File .\eng\Capture-UnifiedAuroraWinUI3.ps1 -Language ru -OutputDirectory C:\Dvinholm-Aurora-RU -IConfirmOfflineNoSecrets
```

For English, select **English** inside Dvinholm, repeat with `-Language en` and **a different empty directory**. Before saving each PNG, the helper verifies both the **currently visible page title** (`DvinholmWorkspaceTitle`) and the **actually selected RU/EN ComboBox item** (`DvinholmLanguageSelector` plus `SelectionPattern`). It repeats these checks after every navigation and immediately before capture; it never resizes or repositions the Dvinholm window. The application owns one fixed **1280 × 800 DIP client viewport**. The helper captures the six approved pages once each for the selected language, producing six PNGs plus one manifest; the complete RU+EN set is **12 PNGs**, not a responsive-width sweep. It measures the real HWND/client geometry and DPI, verifies the fixed client dimensions, and preflights the full window against the monitor work area. If the app was clamped to a smaller viewport or the full target cannot fit, capture refuses: record **NOT RUN** and use a suitable display rather than resizing the window or claiming a pass. Missing or inaccessible UI Automation data also fails closed. These are genuine visible-window captures only, not full scrollable-page screenshots.

Manually compare the actual PNG images against the approved six-page Aurora reference for banner cropping, crest position, Aurora colors, glass-card spacing, fixed first-fold density, readable captions, disabled buttons, panel balance and RU/EN at 100% / 125% / 150% / 200% display scales. A screenshot alone does **not** prove visual equivalence, data correctness or J2534 compatibility. Captures remain local until manually redacted and approved for sharing. All screenshot and visual-comparison acceptance is **NOT RUN** until actual Windows outputs are reviewed.

## Eight bounded checks (record PASS / FAIL / NOT RUN)

1. **Package and executable.** Confirm the reviewed x64 ZIP passes published SHA-256 and extraction checks. Run from a clean user-writable directory, not from inside the ZIP. Confirm there is one primary `Dvinholm.exe` window; the old separate launcher is not required in this new x64 pilot. This is not a certificate-signing test.
2. **Start on clean Windows.** Verify WinUI 3 and the bundled .NET 10 self-contained files launch without unplanned installers or runtime-download prompts. If installation fails, capture sanitized exception type and Windows build only, not usernames or private file paths.
3. **Approved Aurora pages and graphics.** Verify the six primary destinations: Connection, Updates, CEM PIN, CEM configuration, Faults (DTC) and Modules (ECU). There is no seventh Settings destination.
   - **Fixed window:** confirm a 1280 × 800 DIP client area on a monitor that can accommodate it, centered in the work area. Resizing and maximizing must be unavailable; minimizing remains available. Check at 100%, 125%, 150% and 200% display scale that the logical composition remains fixed and that text, icons and controls are not clipped. On a smaller work area the app may clamp once at startup; do not treat that reduced viewport as full visual acceptance.
   - **Aurora identity:** compare the scenic banner, original crest, navy/cyan/violet backdrop and Northern-lights sidebar ribbons against the original approved artwork. The ribbons must not obscure labels, steal input or imply a connected state. All six sidebar icons must be individually centered; RU/EN tooltips and routes must work. The banner and card spacing must preserve the approved visual hierarchy without unintended horizontal scrolling.
   - **Connection and Updates:** verify the first-fold card composition, long RU/EN captions and all visible controls fit inside the fixed viewport. While disconnected, the top-banner dot, bottom status dot and connection text remain neutral grey; they turn green only after a real established J2534 session. Opening Connection, selecting a driver or switching language must not imply a connection. Updates must show the installed version and saved channel accurately; read-only release discovery and ZIP staging must never install, replace or restart the application.
   - **CEM PIN and configuration:** verify the three numbered PIN steps are balanced and readable without implying progress or a successful search. `Inspect prerequisites locally` must show eight conditions and issue no CAN/J2534 requests. CEM configuration must keep third-party and Volvo research labels in separate tiers, preserve the selected canonical research ID across translation, show no fabricated live values, and leave read/backup/compare/prepare/write actions disabled; only the explicitly documented offline Sources action may be active.
   - **DTC and ECU:** DTC must show a distinct filter/read/disabled-clear command area and real session-scoped results only, with no mock fault codes or invented OEM diagnoses. ECU must prioritize passive RX observations, the vehicle side-profile illustration and selected-response details. The XC90 P2 / XC70 P3 drawings must carry a translated **schematic only** disclaimer and must not imply physical module coordinates. Never invent RX frames; if no genuine permitted read-only observation exists, mark populated-list layout and localization checks **NOT RUN**.
   - **Status and completeness:** confirm the six approved pages have the correct localized title, no duplicate oversized page title, no developer-framework or launcher branding, no clipped action or caption, and a distinct lower real-status strip. Compare the complete first fold and visible bottom status area with the approved artwork. A screenshot does not prove hidden content, live adapter behavior or diagnostic correctness.
4. **Language and updates.** Switch RU → EN → RU twice on each primary page. On **Connection** while disconnected, verify the **local adapter metadata card** alternates English `J2534 adapter details: disconnected.` and Russian `Сведения об адаптере J2534: нет подключения.`; no connection or driver version may be implied. If a permitted read-only virtual J2534 session exposes driver versions, check RU/EN switching retains the exact **sanitized API/DLL/FW strings**, capability flags and the prominent *unverified, local only* caveat. Toggle during connecting/disconnecting and verify an old driver's version is never resurrected after reset; the shared home/activity strip must never receive these private vendor values. Mark the connected-session portion **NOT RUN** unless a real permitted adapter/virtual session was exercised. Verify sidebar, workspace caption, CEM PIN safety, CEM configuration rows/filters, DTC titles and previously observed status/details, ECU scan/side-profile captions, connection controls, CAN monitor, ECU profile buttons and integrated Updates controls translate without mixed Russian headings in English mode. When a **genuine passive RX list** is available from a permitted read-only virtual-adapter session, switch RU → EN → RU **after** selecting a record: its row labels must alternate **Кадры / Frames**, **Макс. байт / Max bytes**, **Неизвестно / Unknown** or **Предполагается / Inferred** according to actual inferred-TX evidence, while the original RX/TX IDs, frame counts, selected record and warning provenance stay unchanged. No scan, CAN request or connection attempt may occur on language switching. For **passive ECU discovery outcomes**, validate the full RU→EN→RU transition in three realistic cases if safely available: complete scan with selected RX, cancelled/partial scan with disabled selection, and dropped-frame warning. Verify the **live scan status**, each ComboBox option, and selected read-only evidence (including 11/29-bit, RX and inferred/unknown TX IDs, observed frame count, maximum payload and unverified-address warning) switch language **without** dropping selection, clearing diagnostic results, changing the user-entered UDS TX field or triggering a fresh bus scan. The initial, busy, cancelling, complete, empty, cancelled and failed status messages must remain accurate. Cases not safely reproducible must be **NOT RUN**, not PASS. If no real observations exist, mark this populated-list localization check **NOT RUN** rather than inventing data. Selected category, model, passive RX/DTC record and saved update channel must remain unchanged. A language switch must not start a new CAN/J2534 request, trigger re-read of DTCs, reveal PIN or enable write/erase. Download/staging must not automatically install anything.
5. **J2534 registry audit.** On the Connection page expand **Driver architecture audit**. Record only the counts and category labels. Verify Refresh re-runs a read-only scan and the result never prints any absolute DLL paths or registry subkey paths. A reported PE x64 match is **not** proof of the cable or J2534 API working.
6. **Wrong architecture and fallback.** If a registered x86 vendor DLL is available, verify it is reported as wrong bitness and is not auto-selected by the x64 application. If a vendor installer registers a PE-x64 DLL only under the x86 registry view, verify it is reported as a registry mismatch. Never force-load a synthetic or wrong-bitness DLL.
7. **CEM safety and fixed reference.** On CEM PIN run **Inspect prerequisites locally**; the result must list eight conditions and issue no CAN/J2534 requests. Review CEM configuration in both languages within the fixed 1280 × 800 DIP viewport: third-party and Volvo research labels remain in separate tiers, the selected canonical research ID does not change when translated, no live vehicle values appear, and configuration backup/compare/prepare/write actions remain disabled without transmission. A user profile or generic DID capture must not authenticate physical CEM identity.
8. **Session lifecycle and finish.** With the test adapter or virtual fixture only, observe connect/disconnect, cancellation, and page navigation. A failed or cancelled request must not leave stale identity or PIN status. Close the application and verify no update helper remains running. Record any defects, log references and the exact commit SHA in the PR without copying VIN, PIN, DLL paths, tokens or other secrets.

## Vendor/physical acceptance intentionally not performed

Actual x64 vendor support for **Volvo DiCE** and **Mongoose JLR Pro** remains unknown until a reviewed driver is installed and tested on Windows x64. Driver registry registration, PE architecture, successful DLL load, J2534 API conformance, CAN monitor RX and actual vehicle responses are separate acceptance levels. Physical vehicle and CEM procedures require a later, separately authorized stage with independently validated addressing and safe read-only service semantics.

**Result template:** commit SHA; Windows build; x64 pilot run ID; full regression run ID; test 1–8 = PASS/FAIL/NOT RUN; anonymized symptom and reproducer; operator/date. Do not mark a release ready while required checks remain NOT RUN.
