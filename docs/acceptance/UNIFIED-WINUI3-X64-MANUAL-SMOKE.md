# Dvinholm unified x64: Windows installation and J2534 manual acceptance

**Status: pending hands-on Windows review.** This is an acceptance checklist, not a record of successful physical adapter tests. PR-only CI ZIPs are not signed releases, and production update replacement stays disabled.

## Preparation

Use an isolated Windows 11 x64 test machine with a known restore point / disposable installation. Obtain the ZIP only from the GitHub Actions artifact for the **exact PR head commit** whose automated x64 pilot and full regression runs both passed. Do not treat successful publishing as Windows GUI acceptance. Never use an actual vehicle or live CEM PIN/configuration service for this checklist.

## Optional real desktop screenshot collection (NOT RUN)

This is **not** part of GitHub Actions. The unsigned PR review artifact now includes `eng/Capture-UnifiedAuroraWinUI3.ps1` **beside**, not inside, the production-mode Dvinholm ZIP. Review the helper text before running it; do not execute a modified or mismatched-head copy. Run the opt-in `eng/Capture-UnifiedAuroraWinUI3.ps1` on the same **interactive Windows 11 desktop** where the exact-head PR artifact is open. It captures genuine on-screen window pixels, not XAML approximations, browser mockups or offscreen Windows CI rendering. Before capture: use a **separate, clean x64 review install** with no real J2534 cable or active vehicle session; inspect all visible inputs/status/logs and remove VIN, PIN, DLL paths, usernames and other private data.
```powershell
powershell.exe -NoProfile -File .\eng\Capture-UnifiedAuroraWinUI3.ps1 -Language ru -OutputDirectory C:\Dvinholm-Aurora-RU -IConfirmOfflineNoSecrets
```

For English, select **English** inside Dvinholm, repeat with `-Language en` and **a different empty directory**. Before saving each PNG the helper now verifies both the **currently visible page title** (using the stable DvinholmWorkspaceTitle UI Automation ID) and the **actually selected RU/EN ComboBox item** (DvinholmLanguageSelector and SelectionPattern), not just the filename parameters. The tool attempts six approved pages at 640/800/980/1280/1440 *effective client-area DIP widths*, with 700 DIP client height. It measures real Windows frame/border dimensions, sizes the outer HWND to give the **requested client width**, preflights all widths against the monitor before capture and records actual client/outer pixels and per-window DPI and a local JSON manifest, and **refuses** window-size mismatch, missing accessibility controls, unfit monitor, hidden/covered window, noninteractive CI and screenshot paths inside the Git checkout. If a target cannot fit, do not call it PASS: record NOT RUN with monitor size and use a suitable display. These are **visible viewport captures only**, not full scrollable-page screenshots.

Manually compare the actual PNG images against the approved six-page Aurora reference for banner cropping, brand position, glass-card spacing, first-fold density, readable captions, disabled buttons, panel reflow, 100%/125% display scale, and RU/EN. A screenshot alone does **not** prove visual equivalence, data correctness or J2534 compatibility. Captures remain local until manually redacted and approved for sharing. ## Eight bounded checks (record PASS / FAIL / NOT RUN)

1. **Package and executable.** Confirm the reviewed x64 ZIP passes published SHA-256 and extraction checks. Run from a clean user-writable directory, not from inside the ZIP. Confirm there is one primary `Dvinholm.exe` window; the old separate launcher is not required in this new x64 pilot. This is not a certificate-signing test.
2. **Start on clean Windows.** Verify WinUI 3 and the bundled .NET 10 self-contained files launch without unplanned installers or runtime-download prompts. If installation fails, capture sanitized exception type and Windows build only, not usernames or private file paths.
3. **Approved Aurora pages and graphics.** Verify the six primary destinations: Connection, CEM PIN, CEM configuration, Faults (DTC), Modules (ECU), Updates. Inspect the newly source-aligned **Northern-lights sidebar** behind the original crest and six menu buttons: three low-opacity cyan/teal/violet ribbons must not obscure sidebar labels, steal input, or imply a connected state; at widths below 980 DIP the ribbon should dim visibly while the icon rail remains readable. Verify the **six compact 64-DIP sidebar icons are individually centered in their selected/unselected button surfaces**, not biased by the full-width text padding. Each icon's RU/EN tooltip and route must still work, with no seventh Settings button. At 980+ DIP the original left-aligned wide sidebar labels/padding must return. Confirm the scenic top banner stays legible with a **132-DIP wide minimum** and **116-DIP compact minimum** (content may legitimately increase its actual height), and that matte-gradient cards now use 16-DIP padding / 12-DIP gaps. Check the new first-fold balance against the approved user mockup at 640, 800, 980, 1280 and 1440 DIP; do not claim pixel-level acceptance based on XAML constants. Inspect the navy/cyan/violet backdrop and both distinct, side-view XC90 P2 / XC70 P3 vector silhouettes; neither may claim real module coordinates. At effective widths 640, 800, 980, 1280 and 1440 px and Windows scale 100% / 125%, confirm the header at **less than 980 effective DIP** places true connection status, language selector and visible Cancel UDS action on a **single second row** beneath the title, with no overlap, clipped text or extra vertical stack; at 980+ the actions stay at the right of the banner. Check long RU/EN captions in CEM/ECU/DTC action bars wrap without clipping. At **640/800 client DIP** inspect the compact CEM research table and DTC list specifically: CEM name/code must remain readable next to the three clearly unknown read-only values (76/76/60 DIP respectively), DTC code/description/status must remain aligned (96/flexible/124 DIP), long RU/EN statuses must wrap rather than overlap or truncate. Check 980/1280/1440 DIP too; the source-level table column contracts are not pixel-accurate acceptance. For each run compare the first visible fold and bottom neutral real-status strip with the approved six-page artwork. Additionally, confirm CEM category, parameter list and details stack below 1280 rather than requiring a 730px-wide horizontal scroll. On Connection verify the three first-fold cards (J2534 adapter, CAN parameters, real communication state), and on Updates verify the three panels (installed version, Stable/Development channel, safe update check). Both triptychs must stack vertically below 1280, with no clipped buttons or horizontal scrolling. The connection panel must never show a green success unless a real J2534 session exists. Check all **three** J2534 connection cues: the top-banner dot, bottom status dot and Connection status text must start **neutral grey** while disconnected, and become green only after an actual established J2534 session. Selecting a driver, opening the Connection page or switching RU/EN must not turn any of them green; their color must revert on disconnect/failure. The top status is a navigation button, not a Connect shortcut, and its tooltip must be legible in both languages. CEM configuration must show the four research columns (parameter / original / current / new) without claiming live values. Its six-button action rail must sit **below** the three research panes, wrapping to **three two-button rows** under 1280 effective px; only **Sources (offline)** may have an active handler. Read, backup, compare, prepare and write stay visibly disabled, with explanatory tooltips. The CEM PIN stepper connector is decorative and must show no fake progress. Confirm the removed Settings destination is absent. Confirm the ECU page presents its passive RX list, scalable car outline, and selected-observation details as the primary workspace, **before** the secondary ECU tools. Verify the XC90 P2 / XC70 P3 artwork includes a clearly labeled **schematic-only** stamp (translated RU/EN); it must never show physical ECU positions. The ECU tool buttons must reflow to two columns plus a full-width row below 1280 effective px, without losing their actual navigation handlers. Confirm DTC has a distinct framed filter/read/disabled-clear command rail and a side-by-side result/details workspace at 1280+, stacking the details and three command controls at smaller widths. The table/details must show real, session-scoped results only, with no mock fault codes or OEM diagnoses. **Screenshots for each layout remain NOT RUN until actually captured.**
4. **Language and updates.** Switch RU → EN → RU twice on each primary page. Verify sidebar, workspace caption, CEM PIN safety, CEM configuration rows/filters, DTC titles and previously observed status/details, ECU scan/side-profile captions, connection controls, CAN monitor, ECU profile buttons and integrated Updates controls translate without mixed Russian headings in English mode. Selected category, model, passive RX/DTC record and saved update channel must remain unchanged. A language switch must not start a new CAN/J2534 request, trigger re-read of DTCs, reveal PIN or enable write/erase. Download/staging must not automatically install anything.
5. **J2534 registry audit.** On the Connection page expand **Driver architecture audit**. Record only the counts and category labels. Verify Refresh re-runs a read-only scan and the result never prints any absolute DLL paths or registry subkey paths. A reported PE x64 match is **not** proof of the cable or J2534 API working.
6. **Wrong architecture and fallback.** If a registered x86 vendor DLL is available, verify it is reported as wrong bitness and is not auto-selected by the x64 application. If a vendor installer registers a PE-x64 DLL only under the x86 registry view, verify it is reported as a registry mismatch. Never force-load a synthetic or wrong-bitness DLL.
7. **CEM safety and responsive reference.** On CEM PIN run **Inspect prerequisites locally**; the result must list eight conditions and issue no CAN/J2534 requests. Switch to CEM configuration in both languages and at compact width: third-party and Volvo menu labels remain in separate tiers, selected canonical research ID does not change when translated, no live vehicle values appear, and configuration backup/compare/prepare actions remain disabled without transmission. A user profile or generic DID capture must not authenticate physical CEM identity.
8. **Session lifecycle and finish.** With the test adapter or virtual fixture only, observe connect/disconnect, cancellation, and page navigation. A failed or cancelled request must not leave stale identity or PIN status. Close the application and verify no update helper remains running. Record any defects, log references and the exact commit SHA in the PR without copying VIN, PIN, DLL paths, tokens or other secrets.

## Vendor/physical acceptance intentionally not performed

Actual x64 vendor support for **Volvo DiCE** and **Mongoose JLR Pro** remains unknown until a reviewed driver is installed and tested on Windows x64. Driver registry registration, PE architecture, successful DLL load, J2534 API conformance, CAN monitor RX and actual vehicle responses are separate acceptance levels. Physical vehicle and CEM procedures require a later, separately authorized stage with independently validated addressing and safe read-only service semantics.

**Result template:** commit SHA; Windows build; x64 pilot run ID; full regression run ID; test 1–8 = PASS/FAIL/NOT RUN; anonymized symptom and reproducer; operator/date. Do not mark a release ready while required checks remain NOT RUN.
