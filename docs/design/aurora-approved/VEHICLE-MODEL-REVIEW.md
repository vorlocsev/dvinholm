# Aurora — проверка изображений девяти моделей Volvo

Этот этап **не является подтверждённой визуальной приёмкой**: автоматический Windows CI проверяет сборку, PowerShell-синтаксис и статические контракты, но не делает снимки живого окна WinUI 3.

## Что проверяем

Карточка «Карта автомобиля» в разделе **Блоки** использует локальный SVG-атлас с девятью справочными стилизованными рендерами: XC90 I / XC70 II / V70 II / S60 I / S80 I (P2), XC90 II (SPA), XC70 III / V70 III / S80 II (P3). Это не заводские фотографии, не декодирование VIN, не схема физического расположения блоков и не утверждение совместимости диагностического протокола.

Нужны реальные снимки **каждой модели на русском и английском языках** с неизменяемым клиентским окном 1280 × 800 DIP. На них вручную проверить соответствие подписи автомобилю, отсутствие обрезки кузова/колёс, читаемость текста, нет ли наползания компонентов, реальную загрузку SVG и поведение при масштабировании дисплея.

## Безопасная подготовка

1. Использовать архив `Dvinholm-Windows-x64.zip` и `eng/Capture-UnifiedAuroraWinUI3.ps1` из **одного и того же exact-head Windows x64 pilot PR #702**, а не старый запущенный `Dvinholm.exe`.
2. Извлечь ZIP в отдельный новый каталог, проверить содержимое и метаданные сборки. Запустить этот `Dvinholm.exe` на интерактивном рабочем столе Windows.
3. Отключить физические J2534/DiCE/Mongoose, убрать VIN, PIN, личные пути и прочие секреты из интерфейса. Проверить, что окно целиком помещается на монитор при выбранном DPI.
4. Перед каждой языковой серией вручную выбрать RU либо EN в самом приложении. Снимки хранить только **в новом пустом каталоге вне репозитория**.

Пример для **Windows PowerShell 5.1** из клонированной ветки PR и после ручной проверки сценария (замените `<EXACT_HEAD_40_HEX>` фактическим SHA артефакта):

```powershell
Unblock-File -LiteralPath '.\eng\Capture-UnifiedAuroraWinUI3.ps1'

& '.\eng\Capture-UnifiedAuroraWinUI3.ps1' `
  -Language ru `
  -OutputDirectory 'C:\Dvinholm-Aurora-ModelReview\ru' `
  -IConfirmOfflineNoSecrets `
  -CommitSha '<EXACT_HEAD_40_HEX>' `
  -VerifyWorkspaceScroll `
  -CaptureBottomViews `
  -CaptureVehicleModels

# Изменить язык Dvinholm на English, затем отдельный каталог:
& '.\eng\Capture-UnifiedAuroraWinUI3.ps1' `
  -Language en `
  -OutputDirectory 'C:\Dvinholm-Aurora-ModelReview\en' `
  -IConfirmOfflineNoSecrets `
  -CommitSha '<EXACT_HEAD_40_HEX>' `
  -VerifyWorkspaceScroll `
  -CaptureBottomViews `
  -CaptureVehicleModels
```

`-CommitSha` проверяет соответствие запущенного exe опубликованному PR-артефакту, а не подменяет визуальную проверку. Не запускать сценарий, если в каталоге отсутствует корректное `artifacts/Aurora-x64-build-evidence.json` или проверка происхождения не проходит.

## Что сохраняется

- Шесть исходных снимков страниц в каждом языке и `Aurora-ru-capture-manifest.json` / `Aurora-en-capture-manifest.json`.
- Проверенные нижние снимки только для реально прокручиваемых страниц, с отдельным журналом (непрокручиваемая страница **не получает ложный PASS**).
- Девять дополнительных файлов `Aurora-Ecu-Model-<id>-<language>-1280-dip.png` для каждого языка.
- Отдельный `Aurora-<language>-vehicle-models-manifest.json`, который формируется **только при успешном захвате всех девяти** моделей.

Сценарий выбирает модели только через UI Automation ComboBox `SelectionItemPattern`, подтверждает текущую локаль, выбранную модель и текст подписи, проверяет размер окна и видимость, затем **восстанавливает исходный выбор даже при исключении**. Он не нажимает кнопки подключения, не передаёт CAN-пакеты и не изменяет диагностический контекст. Если UIA-элементы недоступны, проверка останавливается — отсутствие снимка не считается успешной приёмкой. Дополнительно сценарий требует явного статуса `DvinholmVehicleAtlasLoaded` от реального события `ImageOpened` в WinUI 3 непосредственно перед сохранением каждого изображения. Если SVG не декодировался и показана резервная плашка, захват прекращается; статус `ImageFailed` никогда не выдаётся за успешный рендер. Успешное декодирование не заменяет ручной проверки внешности модели и компоновки.

## Результат

После запуска сопоставить все изображения с выбранными моделями и отдельно проверить целостность пиксельного отображения, контраст, подпись SPA для XC90 II, RU/EN, высоту заголовка и нижней панели. Если рендер выглядит ошибочно, заменить или исправить исходное изображение модели, не меняя отображаемые CAN ID.

**Важно:** генеративно выполненные стилизованные модели — лишь визуальные референсы. Точная внешность каждой комплектации и года выпуска здесь не подтверждена. Реальные фотографии или лицензированные модельно-специфичные рендеры можно внедрить отдельно после согласования источника и прав использования.
